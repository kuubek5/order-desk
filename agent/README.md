# KuubMill-агент для ПК верстата

Кладе кадр екрана верстата у мережеву теку, звідки його читає CRM.

## Навіщо він, якщо є VNC

UltraVNC на Windows 7 знімає екран старим способом і **не бачить смугу
відсотка виконання** — RemiCORE малює її поверх звичайного шару. Це
перевірено: у кадрі VNC смуги немає, а через RustDesk вона видно. Агент бере
кадр так, як його бачить сам Windows (`PrintWindow` з
`PW_RENDERFULLCONTENT`), тому смуга потрапляє в кадр.

## Що він робить і чого не робить

Робить рівно одне: раз на 15 секунд зберігає PNG у вказану теку.

**Не вміє за конструкцією:**

* не відкриває жодного порту й не приймає з'єднань;
* не шле верстату ані байта вводу (у коді немає викликів миші/клавіатури);
* не чіпає нічого на диску, крім свого кадру;
* нічого не шле в інтернет.

Увесь агент — один файл `kuubmill_agent.py`, ~140 рядків із коментарями.
Це навмисно: код на CNC-ПК має бути таким, щоб власник цеху прочитав його
сам за хвилину.

## Встановлення

### Варіант 1 — є Python на ПК верстата

```bat
python kuubmill_agent.py --out \\SERVER\share\machine_frames --name 350i-1
```

### Варіант 2 — без Python (звичайний випадок)

Зібрати один .exe на будь-якому ПК із Python і скопіювати на верстат:

```bat
pip install pyinstaller pillow
pyinstaller --onefile --noconsole --name kuubmill-agent kuubmill_agent.py
```

Готовий `dist\kuubmill-agent.exe` покласти на ПК верстата й запускати з тими
самими аргументами.

### Автозапуск

Найпростіше — ярлик у `shell:startup` з аргументами. Надійніше — «Планувальник
завдань»: тригер «при вході в систему», дія — шлях до exe з аргументами,
галка «виконувати, навіть якщо користувач не ввійшов» не потрібна (RemiCORE
і так працює під сеансом оператора).

## Ім'я верстата

`--name` стає іменем файлу кадру (`350i-1.png`) і має збігатися з ключем
верстата в CRM. Без пробілів і кирилиці.
