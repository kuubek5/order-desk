# Контракт ліцензійних ключів (KuubMill / Order Desk)

Ключі цього продукту видає не лише офлайн-скрипт, а й **kuub.win License Service**
(репо `kuubek5/personal-site`, `api/app/licensing/kuubmill.py`). Формат ключа —
**контракт**: сервіс повторює його байт-у-байт. Тихо змінити формат тут = сервіс
почне видавати ключі, які програма відхилить.

## Що саме є контрактом
- `app/license.py`: `verify_license_key`, `encode_license_key`, `_b64url_encode/_decode`.
- `app/license.py`: `_PUBLIC_KEY_BYTES` — вбудований публічний Ed25519-ключ.
- `app/license.py`: `get_machine_id()` — `sha256(MachineGuid)[:16]` (hex, 16 символів);
  клієнт показує його на екрані `/license`.
- `scripts/license_keygen.py` (+ `keygen.py`, `keygen.bat`) — офлайн-видавець.

## Формат
`ключ = b64url(payload_json) + "." + b64url(signature)` (base64url без `=`).
- payload — компактний JSON (`separators=(",", ":")`) з **відсортованими ключами**:
  `{customer, expires_at | null, issued_at, machine_id}`.
- **Підпис рахується над ASCII-байтами base64url-рядка payload**, а НЕ над самим JSON.
- Алгоритм: Ed25519.
- `expires_at` — ISO-8601 із часовою зоною; `null` = безстроковий ключ.
- `machine_id` — 16 hex-символів; ключ жорстко прив'язаний до однієї машини.

## Правила
1. Не змінюй формат, підписувані байти, назви полів, виведення `machine_id`
   чи публічний ключ **без одночасного оновлення сервісу** (той самий change в обох репо).
2. Ротація ключа = **додати** новий ключ, старий лишити. Раніше видані ключі
   мають лишатися валідними назавжди.
3. Ніколи не клади приватні ключі в репо (тести використовують лише тестовий публічний).

## Контрактний тест
```
DB_ENCRYPTION_KEY=Un82ZLqj-Mb9wutrlh4s384pKBsG1WMn1GCYncpWgTw= python -m pytest tests/test_license_contract.py
```
(`DB_ENCRYPTION_KEY` — той самий публічний CI-значення з `.github/workflows/tests.yml`; потрібне лише для імпорту `app.config`.)
Вектори: `tests/fixtures/license_contract.json` (згенеровані сервісом, підписані
**публічним тестовим ключем**, не бойовим). Тест підміняє `_PUBLIC_KEY_BYTES` на
тестовий ключ і перевіряє: ключ валідний на своїй машині (customer, expires_at
збігаються), відхиляється на чужій, зіпсований ключ відхиляється.

**Падіння тесту означає**, що змінилась верифікація/формат. Не «лагодь тест»:
або поверни поведінку, або оновлюй сервіс і перегенеруй вектори разом.

Перегенерація векторів (у репо personal-site):
```
cd api && uv run python -m tools.make_contract_vectors
```
Потім скопіюй новий JSON у `tests/fixtures/license_contract.json` дослівно.

## Відомі прогалини (з аудиту; для обізнаності, зараз не виправляємо)
- Немає захисту від відкату системного годинника.
- Поле `expires_at` необов'язкове (ключ без нього безстроковий).

## Майбутнє
Онлайн-перевірка (v2) має бути **fail-open**: недоступність сервісу не повинна
блокувати роботу клієнта з уже валідним офлайн-ключем.
