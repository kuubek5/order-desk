## CRITICAL
- none. Every finding below needs either local code execution, a local web page, or an already-admin session.

## HIGH
- app/backup.py:58 — `_TABLE_MODELS` covers 13 of 27 mapped tables; the "PC move" backup silently drops `Furnace`, `Machine` (incl. encrypted VNC passwords / agent tokens), `Material`/`MaterialAlias`, `MailFilterRule`/`MailFilterCategory`, `ClientSenderMemory`, `SavedQueueView`, `Feedback`/`FeedbackImage`, `FurnaceReading`, `ActionLog`, `Vyrobitok{Month,Cell,Day}` — i.e. all equipment config, all learned filters, and the payroll tally. Restore also leaves those tables untouched beside freshly re-inserted `users`/`orders`, so ids collide with stale rows. Fix: build the list from `Base.metadata.sorted_tables` and add a test that every mapped table is either covered or on an explicit exclusion list.
- app/web.py:785 — no CSRF token, no Origin / Referer / `Sec-Fetch-Site` check anywhere (verified by grep over `app/`); `same_site="strict"` is the sole defence. SameSite ignores the port, so `http://127.0.0.1:<any other port>` is the SAME site: any other local web page can POST with the operator's cookie to every mutation, and those POSTs also satisfy `is_loopback_request`. Fix: reject state-changing methods unless `Origin`/`Referer` is `http://127.0.0.1:8000` (or `Sec-Fetch-Site: same-origin`), and send `X-Frame-Options: DENY` (same-site framing is likewise allowed today).
- app/services/telegram.py:145,162,190 — `f"мережа: {exc}"` stringifies a `requests` exception whose message embeds the full URL, i.e. `…/bot<BOT_TOKEN>/sendMessage`. That string is persisted plaintext in `Feedback.telegram_error` (services/feedback.py:92 → DB, monthly snapshots, backups), rendered as a `title=` attribute in `templates/_feedback_inbox_list.html:41`, and put in the session cookie by `routers/settings/feedback.py:118`. Fix: classify the failure like `connections.py::_imap_error_reason` does and never let the URL out of this module.
- app/update_check.py:293 + app/sheets.py:212 — installer trust chain is TLS-to-GitHub plus a SHA-256 fetched over the same channel, and `_LegacyRenegotiationAdapter.init_poolmanager` deliberately trusts the Windows cert store — which contains the lab's TLS-inspection proxy CA. Whoever controls that proxy (or can add a root CA) serves a forged `.exe` plus a matching `.sha256`; `_strip_mark_of_the_web` (line 346) then removes the last SmartScreen gate and the watchdog runs it `/VERYSILENT`. Fix: ship a detached Ed25519 signature of the installer and verify it with the product public key already present at `app/license.py:34` before `launch_silent_install`.
- app/db.py:14 — `PRAGMA foreign_keys` is never enabled (only `journal_mode`/`busy_timeout`), so every `ForeignKey` in `models.py` is decorative under SQLite. `backup.restore_backup:187` bulk-deletes with `query(model).delete()`, and `delete_machine`/`delete_furnace` (devices.py:431,185) leave `action_log`, `status_events`, `feedback_images`, `furnace_readings` pointing at gone rows. Fix: enable it in the same `connect` listener, add explicit `ondelete` where cascade is intended, and re-check the restore order under enforcement.

## MEDIUM
- app/windows_launcher.py:313 — `uvicorn.Config(...)` leaves `proxy_headers=True` and `forwarded_allow_ips` defaulting to `"127.0.0.1"` (verified against uvicorn 0.52.0), so `ProxyHeadersMiddleware` rewrites `scope["client"]` from a caller-supplied `X-Forwarded-For`. `deps.is_loopback_request:104` is therefore header-derived, not connection-derived: any local page can send `X-Forwarded-For: 8.8.8.8` and make every loopback-gated admin action 403. Fails closed, but the control is not what it claims. Fix: `proxy_headers=False`.
- app/routers/deps.py:117 vs settings/* — the loopback rule is applied inconsistently, the same drift §14 says was fixed. NO loopback check: `POST /settings` (writes `imap_password`, `google_service_account_json`, `google_oauth_refresh_token`, `license_key` — overview.py:379), `POST /settings/imap` (connections.py:116), `POST /settings/test-imap` (connections.py:151), and all four routes in settings/users.py (create operator / reset password / toggle active). WITH it: `/settings/test-sheets`, `/settings/update/*`, `/settings/backup/*`, `/diag/*`, device passwords. Pick one rule and encode it in `require_settings_edit`'s default.
- app/routers/settings/devices.py:282,308 — `machine_calibration_path` is operator-editable (`settings_nav.py:199` `machines edit_roles=None`); `services/machines.py:452,511,529` writes JPEG frames under it and `/settings/machines/calibration-folder` `mkdir(parents=True)`s it. That is precisely the "write a file into an arbitrary network share" primitive that `overview.py:125-131` deliberately kept admin-only for the path probe. Make the calibration path admin-only or confine it under `runtime.data_dir()`.
- app/db.py:16 — `create_engine` takes pool defaults: `QueuePool(size=5, max_overflow=10)` = 15 connections, while 13 background workers hold sessions across network calls (`web.py:736-750`) and each page render opens ~8 short-lived ones (`license_gate` + `notify_prefs`/`shift_pending`/`feedback_open_count`/`busy_operators`/`sync_state`/`ui_prefs` + `get_db`). A slow sync can exhaust the pool and block requests 30 s before `TimeoutError`. Size it explicitly (or `NullPool` for local SQLite) and measure — this matches the "пул зʼєднань вичерпувався" note already in memory.
- app/backup.py:150 — restore reconstructs `User` rows verbatim from the file, `role='адмін'` and `password_hash` included, and `confirm_replace` is a form field, not a defence. Combined with HIGH#2 (no CSRF) one same-site POST replaces every account. It also ignores `format_version` (line 168 only reads `kdf_iterations`). Fix: reject unknown `format_version`, and require re-authentication (password re-entry) for restore.
- app/web.py:878 — the license_gate docstring claims it "runs outermost"; it does not. `add_middleware` inserts at index 0, so the actual outside-in order is ServerError → `log_slow_requests` → `license_gate` → `no_store_html` → `SessionMiddleware` → Exception → router (the note at line 954 is the accurate one). Consequence to keep in mind: `license_gate` runs BEFORE `SessionMiddleware`, so `request.session` does not exist there. Fix the stale docstring before someone adds a session read to that gate.
- app/routers/settings/* — no settings mutation writes an `ActionLog` entry. Changing the IMAP password, replacing the service-account JSON, switching the license key, deleting a machine and restoring a backup are all untracked, while order-level actions are fully journalled. On a shared workstation with two operators that is the audit trail that matters most.
- app/config.py:99 — `SESSION_SECRET_KEY` is `sha256("order-desk-session:" + DB_ENCRYPTION_KEY)`, so it cannot be rotated without rotating the DB key (which orphans every stored secret). Related: `routers/auth.py:444` changes `password_hash` without invalidating other sessions, and there is no session-version column — a stolen cookie survives a password reset for the full 8 h `max_age`.

## Verified OK
- Alembic: exactly one head (`0047_vyrobitok_day_freeze`), one base (`0001_initial`), 47 linear revisions, every one has a `downgrade`. Data migrations 0016/0017/0019/0022 are idempotent (existence checks first) and 0019 explicitly refuses to override an operator's "all popups off" choice.
- `sheet_backup._safe_snapshot_path:368` blocks traversal three ways (ISO-date parse, `.csv` suffix, `relative_to` on resolved paths); all `/settings/sheets/download*` routes are gated.
- Open redirects: `sections.py:56` and `clients.safe_return_to:263` reject non-`/` and `//`, AND Starlette 1.3.1 `RedirectResponse` percent-encodes `\`, CR and LF — so neither `/\evil.com` nor header injection through `back`/`return_to`/`error` works.
- License: Ed25519 over the base64url payload, machine id = SHA-256 of the Windows `MachineGuid` (raw GUID never displayed), expiry compared in the payload's own tz, every failure path returns a `LicenseStatus` and none raises. `/license` is exempt from the gate but requires login once a valid key and users exist (`auth.py:79`) — the F4 hole is genuinely closed.
- Secrets never enter the Jinja context: `overview.py:196-198` masks `SECRET_SETTING_KEYS` and passes only a "задано" flag; `get_setting` degrades to `None` on `InvalidToken` instead of 500ing the whole app.
- Backup crypto: PBKDF2-HMAC-SHA256 @480k + Fernet; a wrong password fails the auth tag rather than yielding garbage.
- `download_and_verify` treats a missing checksum asset exactly like a mismatch — unlinks the file and raises — and never returns an unverified path.
- Password policy is single-sourced (`operators.PASSWORD_MIN_LENGTH=10`) and enforced by `/setup`, `/account/password`, admin create and admin reset; role is validated against a closed set. The login limiter is lock-protected and keyed username+IP.
- No `shell=True` anywhere in scope; `launch_silent_install` passes an argv list and the watchdog `.ps1` is a constant written by the app, not composed from input.
- OpenAPI/docs/redoc disabled; `/health` returns only status+version; `/diag/*` is admin+loopback and `/diag/perf/client` accepts only floats keyed by a request id the server itself issued.
- `ensure_schema` refuses to start on an unrecognised unversioned schema, backs up before every migration, and re-verifies the schema against the models afterwards — the `create_all` drift class is properly closed.
- UNC handling in `schema._table_names`/`_matches_models` correctly avoids `uri=True`; `_row_to_dict`/`_dict_to_row` round-trip dates via `python_type`.

## Architecture notes
- The single-registry idea (`settings_nav`) works, but three consumers still keep private copies: `palette.COMMANDS`, the per-route role checks in `settings/users.py` and `settings/update.py`, and the loopback decision. Folding role+loopback into one `NavItem` field would remove the whole MEDIUM#2 class.
- Auth is spread over four shapes — `require_admin`, `require_settings_admin`, `require_settings_edit`, and hand-written `if user.role != "адмін"` blocks in users.py/update.py/backup.py/feedback.py. The hand-written ones are the ones that drifted.
- `deps.py` has become the second god-module (594 lines: DB session, auth, templates, toasts, 8 Jinja globals each with its own session). The per-render session count is a direct consequence and is what makes MEDIUM#4 bite.
- Background workers are uniform and correct: each owns its session, catches broadly, and never lets an exception kill its thread. `_BackgroundWorker` is the right abstraction; the only gap is that `stop()` joins 1 s × 13 = up to 13 s against uvicorn's 10 s graceful timeout.
- The "хибне число гірше за жодне" doctrine is applied rigorously in `settings_status` except where the context is role-filtered upstream (LOW: `_slab_operators`).
- Error handling is disciplined: exception text never reaches the browser (`web.py:803`), Google/IMAP errors are classified into actionable Ukrainian, and `human_update_error` does the same for updates. Telegram is the one module that skipped this — and it is the one leaking a secret.
