**Метод.** Dev-сервер 8002 на master `7817154`. (1) Кожен GET-роут з `tests/route_inventory.txt` — curl
з кукі адміна й оператора (`get_sweep.txt`, `op_sweep.txt`); (2) скріншоти всіх екранів і всіх секцій

## 1. Підсумок одним абзацом

Застосунок робочий: усі 52 GET-роути — 200 для адміна, оператор отримує 403 рівно там, де треба;
жодної помилки в консолі; усі кнопки «Перевірити» повертають результат; 1970 тестів зелені, ruff чистий;
жодного href/hx-* на неіснуючий роут; жодної кнопки без обробника. Проблеми — не «зламано», а
**вага, дублювання й межі ролей**: вкладка «Раніше» тягне 5,5 МБ кожні 15 с, сторінка налаштувань —
375 КБ через повний журнал змін, прийняття листа досі блокує event loop, оператор бачить редактор
фільтрів, у якому кожна кнопка дає 403, а сторінка ліцензії відкрита без входу. Плюс організаційне:
паралельний чат опублікував реліз **v0.10.5 ПІСЛЯ v0.11.1** — GitHub тепер вважає «latest» = 0.10.5.

## 3. Критичне / організаційне

### 3.1 Реліз v0.10.5 опубліковано після v0.11.1 (паралельний чат, 22:48) — знято о 22:59
`gh release list` о 22:50: `v0.10.5 Latest`, `v0.11.1` старіший. На той момент кнопка «Перевірити
оновлення» на dev показувала «У вас найновіша версія (v0.10.5)», а банер у рейці — «Доступне
оновлення v0.11.1»: два джерела правди розійшлись через сам реліз, не через код. О 22:59 той самий
чат випустив **v0.11.2 (latest)** — колізія знята, прод оновити до 0.11.2. Урок: `bump_version.py`
має відмовлятися штампувати версію, нижчу за найновіший тег (`git tag --sort=-v:refname | head -1`) —
крок O.4 у PLAN.md. Копія «У вас найновіша версія» при **невдалому** запиті до GitHub теж вводила
в оману — виправлено (§6, F7).
