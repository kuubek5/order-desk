# План після аудиту 05.09.26 — робочий трекер

Джерело: `AUDIT.md` поруч (зведення) + детальні звіти `review_*.md`, `ux_*.md`.
Цей файл — **живий**. Кожен новий чат читає його ПЕРШИМ, робить один крок (або одну групу),
і в кінці оновлює статус тут. Так одна робота не робиться двічі.

## Як користуватись

- Статуси: `⬜` не почато · `🔄` в роботі (вкажи гілку) · `✅` готово (коміт/реліз, дата) · `⏸` відкладено (чому) · `❌` вирішили не робити.
- Один чат = один крок або одна група (A, B, …). Закінчив → коміт → познач тут → новий чат.
- Паралельні чати — тільки в окремих `git worktree` (CLAUDE.md §15).
- Бриф для чату: «Зроби крок **X.N** з `design/audit_2026-09-05/PLAN.md`». Деталі коду — у відповідному `review_*.md`, не переказувати.
- Після групи: повний тест-прогін + два сторожі (`test_route_inventory`, `test_frontend_assets`).
- **Крок позначено `⚠ ЗВІРИТИ З РОМОЮ` → спитати ПЕРЕД роботою, чи влаштовує кінцевий результат.** Це висновки аудитора-агента, не факти з коду — можуть бути неправильні (приклад: 2.2 пропонував злити Виробіток зі Статистикою, хоча Виробіток рахує зарплату й має свою логіку, яку зливати не можна). Без позначки — можна виконувати без питань.

Легенда колонки «Загроза»: **якщо НЕ зробити** — що болить далі; **якщо зробити невдало** — що можна зламати самою правкою.

**2.1 / 2.2 (не робимо) — два замки, два звіти.** Стата й Виробіток рахують «одиниці» різними правилами → цифри розходяться, ніхто не розуміє чому.
**⚠ ЗВІРЕНО З РОМОЮ (06.09.26): злиття 2.2 — НЕ робити як «один розділ».** Виробіток рахує зарплату і має свою логіку (СЛМ окремо, `off_queue`, памʼять `project_slm_tally_rules`) — вона не еквівалентна Статистиці, об'єднання ризикує зламати підрахунок зарплати. Якщо і робити — то лише спільну бібліотеку розрахунку як внутрішній рефакторинг, БЕЗ зміни інтерфейсу/розділів і БЕЗ зміни правил підрахунку Виробітку. Обговорити з Ромою перед стартом, що саме об'єднуємо.

**2.7 — чотири `require_admin`.** Чотири різні перевірки «це адмін» → одну забудеш. Асиметрія loopback-гейта (L-2/3) закривається тут же. Загроза правки: `/settings/furnaces/password` мусить лишитись ВИЩЕ `/settings/furnaces/{id}` (CLAUDE.md §14).

**2.8 / 2.9 — роутери-гіганти.** Бізнес-логіка в HTTP-шарі = не тестується окремо; саме там сиділи C-1 і C-2. Загроза правки: сторож `route_inventory` мусить лишитись зеленим без зміни знімка (множина роутів не змінюється); `monkeypatch.setattr(web, "X")` після переносу стає no-op — перевіряти, що підміна влучає.

**2.10 — 589 КБ three.js на сторінці входу.** ~412 КБ CSS на кожній сторінці. Легкі сторінки → 60-80 КБ. Загроза правки: порядок `<link>` у `base.html` Є каскадом — не міняти порядок, лише умовність; сторож `test_frontend_assets` оновити свідомо.

**2.11 — тести.** 48 із 106 файлів дублюють `create_engine(StaticPool)`. `InvalidToken`-деградація названа критичною в CLAUDE.md, тесту нема.
