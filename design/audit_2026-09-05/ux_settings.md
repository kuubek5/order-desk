# UX-аудит: Налаштування, Setup, Ліцензія, Вхід, Діагностика, Оновлення, Бекапи, Копії таблиці

Джерела: app/routers/settings.py (2280 р.), app/routers/auth.py, app/templates/settings.html + 17 _settings_*.html, app/templates/_topbar_nav.html, app/static/js/settings.js, app/static/js/settings_console.js, app/license.py, app/backup.py, app/monthly_backup.py, app/update_check.py, CLAUDE.md пар.1,7,9.6,14.

## 0. Як це насправді влаштовано (важливо для решти звіту)

/settings — НЕ одна довга сторінка, що скролиться. Усі 13 розділів рендеряться в DOM одночасно (app/templates/settings.html:51-72), але settings_console.js:26-50 показує рівно один .scon-sec через .is-shown, решта приховані. Перемикання — через ліву рейку (_topbar_nav.html:34-165), #hash, або палітру Ctrl+K (settings_console.js:62-163). Тобто це де-факто вкладки/майстер, а не «простирадло»; але код і партіали фізично зверстані як послідовний список секцій.

Окремі повноцінні сторінки поза цим SPA-подібним /settings: /settings/materials (бібліотека матеріалів), /settings/recognition (розпізнавання пошти), /settings/feedback (Telegram-пуш) — мають своє повне перезавантаження сторінки, хоча рейка зліва та сама (_topbar_nav.html:108-119).

## 1. Карта розділів (порядок появи в DOM / рейці)

Рейка групує так (_topbar_nav.html): Стан -> Джерела робіт -> Обладнання -> Інтерфейс -> Обробка пошти -> Люди й система. У settings.html порядок include: _settings_state, _settings_notifications, потім (лише адмін) _settings_google, _settings_operators, _settings_sections, _settings_backup, _settings_sheet_backup, _settings_imap, потім (усім) _settings_paths, _settings_mail_download, _settings_mail_filters, _settings_furnace, _settings_machines, _settings_about.

1. Стан системи (_settings_state.html) — огляд конвеєра (пошта/спул/черга/архів), heartbeat пошти й таблиці, самоперевірка (7 проб), «вага таблиці». Усі бачать карту; кнопки перевірки — адмін. 0 полів, 2 кнопки (адмін).

2. Спливаючі сповіщення (_settings_notifications.html) — стиль тоста (скло/картка), позиція на екрані, які системні події спливають. Усі (особисте, не адмінське). 2 радіо-групи + N чекбоксів + «показати приклад» + «Зберегти».

3. Google Таблиця (_settings_google.html, крок 1) — Sheet ID, режим авторизації (сервісний акаунт / OAuth), JSON-ключ або OAuth-клієнт, разові дії (імпорт історії, звірка видалень). Адмін. ~4 поля, 7 кнопок.

4. Оператори (_settings_operators.html, крок 2) — список User: ім'я/логін/роль/літера/статус/скидання пароля; додавання оператора; ПІН розділу «Виробіток». Адмін. Таблиця N х 7 + форма додавання (5 полів) + форма ПІН (1 поле).

5. Блокування розділів (_settings_sections.html) — прапорці «розділ у розробці/тестується» + аудиторія (усі ролі / конкретні ролі) на кожен закритий розділ. Адмін. По рядку на розділ: select стану + N чекбоксів ролей + «Застосувати».

6. Резервна копія (_settings_backup.html, крок 3) — повний зашифрований бекап БД (пароль-переносний), відновлення з бекапу, read-only список авто-місячних знімків. Адмін. 2 паролі + submit (експорт); файл+пароль+чекбокс+submit (імпорт).

7. Копії Google-таблиці (_settings_sheet_backup.html) — авто-знімання CSV по вкладках (увімк/період год), ручний знімок, завантаження по дню/місяцю/усе. Адмін. Тоггл + степер годин + «Зберегти», «Зняти копію», список завантажень.

8. Пошта IMAP (_settings_imap.html, крок 4) — логін/пароль IMAP, перевірка з'єднання. Адмін. 2 поля, 2 кнопки.

9. Шляхи папок (_settings_paths.html, крок 5) — export_folder_path, technician_files_path, sum3d_projects_path, час початку робочого дня. Оператор теж має доступ (єдиний крок майстра, відкритий не-адміну). 4 поля, 3 кнопки «Перевірити шлях» (live HTMX), «Зберегти».

10. Скачування вкладень (_settings_mail_download.html) — глобальний тоггл «лише довірені / усі підряд», ручне очищення тимчасового спулу пошти. Адмін. 1 сегмент-перемикач + 1 кнопка очищення.

11. Фільтри пошти (_settings_mail_filters.html) — правила категоризації листів (3D-друк, бухгалтерія, спам), той самий панель що й у тріажі. Адмін.

12. Пічки спікання (_settings_furnace.html) — список пічок (назва/host/port/enabled/пароль), спільний VNC-пароль, фон екрана «Пічки». Адмін. Таблиця N х 6 + форма додавання (5) + спільний пароль + тоггл фону.

13. Верстати (_settings_machines.html) — список верстатів (портрет/назва/host/port/enabled/калібрування/токен агента/VNC-пароль), спільний пароль, інструкція встановлення агента. Адмін. Таблиця N х 9 + форма додавання (7) + спільний пароль.

14. Про застосунок (_settings_about.html) — версія, ручна перевірка й встановлення оновлення, журнал змін (CHANGELOG). Усі бачать версію й changelog; кнопка перевірки — адмін.

Поза цим списком (окремі сторінки з групи «Обробка пошти»):
- Матеріали (settings_materials.html + _matlib_detail.html) — бібліотека матеріалів/синонімів, живий пробник правила (admin, app/routers/settings.py:797-947).
- Розпізнавання (settings_recognition.html) — матеріал за замовчуванням для листа без сигналу (admin).
- Зворотний зв'язок (settings_feedback.html) — Telegram-бот токен/chat_id, прив'язка чату, тестове повідомлення (admin, settings.py:2133-2280).

## 3. Де живуть налаштування: БД vs .env vs localStorage vs акаунт

БД (app_settings, зашифровано Fernet/DPAPI, settings_store.py): Google Sheet ID/JSON/OAuth, IMAP логін/пароль, шляхи export/technician_files/sum3d_projects, license_key, day_rollover_time, mail-download toggle, notify style/position/events, sections gate, furnaces/machines (host/port/enabled/password/token), спільний пароль пічок/верстатів, sheet-backup enabled/interval, telegram bot token/chat_id, vyrobitok_pin, material aliases (окремі таблиці), mail filter rules.

.env: лише DB_ENCRYPTION_KEY (ключ шифрування, згідно CLAUDE.md пар.7) — навмисно єдиний виняток, задокументований і послідовний.

Акаунт користувача (User модель, через /account/*): тема інтерфейсу, стиль іконок/кнопок/лоадера/чипів, арт і смуга верстатів на віджеті, картка верстата, порядок віджетів (drag-n-drop side/strip), метрики стрічки навантаження, «вигляд» списків (density/row_pad/list_width/mat_style/layout для mail/queue/handout), пароль, власна літера в таблиці (sheet_initial).

localStorage (побіжно, за коментарями CLAUDE.md пар.14): згортання смуги печей на черзі — «клас на body + localStorage», а не БД/акаунт — ще один шар налаштувань поза /settings і /account.

Логічність розкладки — оцінка:
- В цілому послідовно: секрети та бізнес-конфіг -> БД; персональні візуальні преференції -> User-акаунт; ключ шифрування -> .env. Межа проведена явно і документована (пар.7).
- Прикордонні випадки, не очевидні користувачу:
  - day_rollover_time (коли починається робочий день) — це радше системний/операційний параметр (впливає на всіх операторів), але лежить у тій самій формі й на тому ж кроці «Шляхи папок», доступному оператору, поряд із суто локальними шляхами файлової системи.
  - sheet_initial дублюється у двох незалежних формах: адмін керує ним для будь-кого (_settings_operators.html:34-40), а оператор — сам для себе (POST /account/initial, auth.py:367-388). Валідація однакова, але два UI-шляхи до одного поля — ризик тихого взаємного перезапису.
  - Згортання смуги печей — localStorage, хоча концептуально це такий самий «вигляд списку», як queue_side_order у БД-акаунті. Непослідовно: одні preferences переживають зміну ПК (акаунт у БД), інше — ні.
  - vyrobitok_pin — «секрет», але зберігається в загальному app_settings, показаний у розділі «Оператори»; логічно ближче до «Блокування розділів» (та сама ідея — код доступу до розділу).

## 4. Небезпечні дії без підтвердження / із зайвим підтвердженням

Без підтвердження, хоча деструктивні або з широким ефектом:
- «Встановити vX» (оновлення) — качає й ставить оновлення, перезапускає застосунок одним кліком, без confirm() (_settings_about.html:34-36, settings.py:1969-2009). На спільному робочому ПК посеред зміни це може перервати оператора без попередження.
- Скинути пароль оператора (_settings_operators.html:47-50) — миттєво змінює чужий пароль без підтвердження і без індикації складності/довжини.
- Увімкнути/Вимкнути оператора (toggle-active) — без confirm(), пом'якшено лише тим, що не можна вимкнути себе.
- Зберегти спільний VNC-пароль пічок/верстатів — впливає одразу на всі пристрої без власного пароля, без попередження про кількість зачеплених пристроїв.
- Імпортувати всю історію (Google-таблиця) — важка операція («може зайняти час через проксі»), лише під розкривачкою «Разові дії», без confirm — на відміну від сусідньої «Звірити видалення», яка має докладний confirm. Непослідовність між двома «важкими» кнопками поруч.
- Відновити з бекапу — рятує обов'язковий чекбокс confirm_replace у формі, але немає JS confirm() на сам клік «Відновити»; випадковий повторний клік із вже відміченим чекбоксом (наприклад, після невдалої спроби) миттєво перезапише все без другого попередження.
- Відключити Google OAuth — редирект без confirm, хоча ефект — розрив синку таблиці.

Із «зайвим»/нечітким підтвердженням:
- Звірити видалення (_settings_google.html:161-168) — довгий confirm() з описом внутрішньої механіки запобіжника («>5 робіт і >25%»), що для оператора радше деталь реалізації, ніж інструкція до дії; текст сам визнає «повернуться наступним синком», що трохи суперечить власному тону «небезпечно».
- Видалення пічки/верстата — confirm() є, коректно сформульовано.
- Очищення спулу пошти — confirm() є з деталями обсягу, коректно.

Загальна картина: принцип «один клік, без зайвих підтверджень» з CLAUDE.md пар.2 писався для екрана Черги/Видачі, і в Налаштуваннях застосований непослідовно — одні деструктивні дії (оновлення, скидання пароля) не мають жодного бар'єру, інші (звірка видалень) — з докладним текстовим попередженням.

## 5. Тестові/діагностичні кнопки

- Перевірити доступ (Sheets) -> POST /settings/test-sheets -> «Доступ підтверджено · N вкладок» або класифікована помилка (без сирого тексту Google/gspread).
- Перевірити з'єднання (IMAP) -> POST /settings/test-imap -> результат LOGIN на збереженому паролі, класифікована причина помилки.
- Перевірити шлях (x3) -> POST /settings/check-path -> exists/is_dir на export/technician/sum3d шляхах, живий HTMX (blur + debounce 600мс).
- Запустити самоперевірку -> POST /settings/selfcheck -> 7 проб послідовно (стрім NDJSON): Sheets, IMAP, export-папка, technician-папка, диск >=2ГБ, свіжість бекапу (>40 днів = warn), наявність оновлення. Кожна — ok/warn/detail/ms, живий прогрес по карті конвеєра, підсумок «passed/total», копіювання звіту текстом.
- Перевірити вагу таблиці -> POST /settings/sheet-weight -> рахує правила умовного форматування вкладки (причина гальмування, лише читання).
- Скопіювати machine ID -> JS (ліцензія) -> копіює для передачі власнику продукту.
- Тестове повідомлення (feedback) -> POST /settings/feedback/test -> шле реальне повідомлення в Telegram, показує «Надіслано» / помилку.
- Прив'язати чат (feedback) -> POST /settings/feedback/bind -> ловить chat_id з останнього /start в бота.
- Живий пробник правила матеріалу -> GET /settings/materials/probe (HTMX on input) -> скільки робіт зловить правило ще ДО збереження, чи не відбере роботи в іншого матеріалу.

Усі тестові дії — read-only проби (крім Telegram-тесту, який реально шле повідомлення), жодна не мутує конфігурацію; узгоджено з CLAUDE.md пар.14 «Секрети».

## Прогалини

1. [Високий] Немає журналу синку/подій. «Стан системи» показує лише живий heartbeat (працює/не працює) і статичні лічильники, без історії «коли востаннє синкнулось, скільки рядків, які помилки за тиждень». Модель SyncLog існує (app/backup.py:47 імпортує SyncLog), але в UI Налаштувань немає екрана перегляду цього логу.

2. [Високий] «Встановити оновлення» без підтвердження і без прев'ю ризику. Один клік перезапускає весь застосунок на робочому ПК, потенційно посеред зміни оператора видачі. Немає «встановити пізніше», немає попередження про перезапуск чи перевірки активної сесії видачі.

3. [Високий] Дублювання «літери в таблиці» (sheet_initial) у двох незалежних формах — /settings (адмін, для будь-кого) і /account/initial (сам оператор) — без взаємного відображення «востаннє змінено ким і коли». Ризик тихого перезапису одне одним.

4. [Середній] Немає єдиного «Стан здоров'я»/дашборда, що агрегує самоперевірку + heartbeat + вагу таблиці + спул в один статус-індикатор верхнього рівня (наприклад бейдж у топбарі поза Налаштуваннями). Зараз усі три живуть у розділі «Стан системи» як окремі ручні дії.

5. [Середній] Відсутній експорт/імпорт саме конфігурації окремо від повного бекапу даних. Є лише «все або нічого» (/settings/backup/export) — разом із замовленнями/клієнтами. Немає легкого способу перенести/скопіювати конфіг (Sheets ID, шляхи, фільтри пошти, пічки/верстати) на тестовий стенд чи для підтримки без клієнтських даних.

6. [Середній] «Разові дії» Google-таблиці не консистентні за рівнем обережності: «Імпортувати всю історію» (важка, довга) — без confirm і без індикатора прогресу; «Звірити видалення» поруч — з довгим технічним confirm. Важко відчути відносну «вагу» цих двох кнопок під однією розкривачкою.

7. [Середній] Розділ «Оператори» перевантажений: список User + ПІН «Виробітку» + форма додавання в одній картці. ПІН логічно не пов'язаний з керуванням акаунтами — це радше налаштування доступу до екрана, як «Блокування розділів» нижче. Варто перенести або уніфікувати патерн «код доступу до розділу X».

8. [Середній] Немає перегляду/статистики бекапів окрім розміру файлу. Автоматичні місячні знімки показані списком «ім'я + розмір», без читабельної дати створення, без кнопки «завантажити»/«відновити з цього знімка» прямо з UI (треба лізти у файлову систему backups/monthly).

9. [Низький] «Про застосунок» змішує версію/оновлення (дія) і журнал змін (довідка) в одній картці під одним accordion — для оператора це виглядає інформаційним блоком, для адміна — ще й функціональною дією.

10. [Низький] Таблиці пічок і верстатів майже ідентичні структурно (host/port/enabled/password), але верстати мають ще 5 колонок (портрет/калібрування/токен) — 9 колонок разом, потребують горизонтального скролу; немає згортання неактивних (вимкнених) пристроїв у довгому списку.

11. [Низький] Немає inline-попередження про ризик при перемиканні google_auth_mode (service_account <-> OAuth) під час активного синку — блоки полів миттєво ховаються/показуються без пояснення наслідків для наступного синку.

12. [Низький] /diag/perf існує окремо від /settings, не лінкований з рейки Налаштувань і не згаданий у «Стан системи» — природний шлях адміна («чому гальмує») веде в Стан системи -> Вага таблиці, а окрему сторінку швидкодії він може не знайти.

13. [Низький] «Копії Google-таблиці» та «Резервна копія» (БД) — дві концептуально різні секції («бекап усього з паролем» vs «CSV-знімки вкладок Google»), розташовані одна під одною з дуже схожою візуальною подачею; варто розвести назвами чіткіше або додати спільну пояснювальну фразу різниці перед обома блоками.
