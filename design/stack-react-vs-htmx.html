React чи HTMX

Порівняння на реальних цифрах цього репозиторію, а не на загальних міркуваннях. Питання не «що краще взагалі», а що вигідніше саме тут: один розробник, двоє операторів, 92 рядки на день, standalone Windows.

Вердикт Коротко: лишаємось. Але один аргумент за React справжній, і його треба закрити окремо.

Перехід не окупається: він множить кількість місць на фічу, додає другий тулчейн в інсталятор і вимагає ~100 JSON-ендпоінтів там, де зараз роут віддає HTML напряму. Проте app.js на 1545 рядків і CSS на 7868 — це реальний борг, і його треба лікувати. Просто не React'ом.

Одна цифра варта окремої уваги: app.js — 1 545 рядків. Це один файл з делегованими слухачами на всі екрани застосунку. Саме він, а не «відсутність React», є джерелом відчуття, що фронтенд стало важко правити.

Що дає перехід, що дає залишитись

Позначка праворуч від пункту каже, коли він спрацьовує: вже сьогодні чи лише в перспективі.

React дає
  • Ізоляцію компонентів. Кнопка = один файл зі своїм станом і стилем. Наші 7 868 рядків CSS без scope перестають бути міною зараз
  • Готові доступні компоненти. Radix / shadcn: модалка, комбобокс, тултіп — з клавіатурою і screen reader'ом з коробки. Ми пишемо це руками зараз
  • Типи наскрізь. TypeScript ловить «поле перейменували на бекенді, шаблон мовчки порожній» — зараз це знаходиться очима зараз
  • Вихід AI-інструментів. v0 / Lovable / Bolt віддають React. Лягало б у код без переписування зараз
  • Віртуалізацію таблиць. TanStack Table тримає десятки тисяч рядків. У нас 92/день — поки не болить потім
  • Складний клієнтський стан. Драг-дроп планувальник завантаження верстатів, редактор на канві — там ручний DOM перетворюється на кашу потім
  • Ринок праці. Якщо колись треба буде найняти фронтендера — React знайти незрівнянно легше потім
Поточний стек дає
  • Нуль другого тулчейну. Зараз збірка = PyInstaller + Inno Setup. Node додає крок у release.yml, lockfile, npm-аудити, ще одну вісь оновлень зараз
  • Одну мову стану. 100 роутів віддають HTML прямо з SQLAlchemy. SPA вимагає ~100 JSON-ендпоінтів + схеми + типи + клієнтський fetch зараз
  • 899 тестів, що бачать фінальний HTML. Pytest перевіряє те, що реально піде в браузер. З SPA половина логіки їде в JS і потребує окремого раннера зараз
  • Стійкість до збою JS. Форми — звичайні <form method="post">. Сторінка працює навіть частково. SPA при помилці білить екран — у цеху це не абстракція зараз
  • Швидкість фічі. Шаблон + роут. Проти: ендпоінт → схема → fetch → стан → компонент зараз
  • Одне місце правки для AI-агента. Соло-розробник + Claude: фіча в одному файлі правиться надійніше, ніж синхронізація чотирьох потім
  • Малу поверхню старіння. HTMX 1.9 працюватиме через п'ять років. npm-екосистема ламається щопівроку потім

Що робити натомість

Аргумент про ізоляцію справжній. Ось три способи закрити його, не платячи за міграцію.

КрокЦінаЩо лікує
Розбити app.js по екранахОдин вечір1 545 рядків делегованих слухачів → файл на екран. Найбільша віддача за найменші гроші
Розбити CSS по екранахОдин вечір7 868 рядків без scope. Частково вже є: clients.css, stats.css, settings.css

React-острів на одному екраніПомірнаЯкщо колись зʼявиться планувальник з драг-дропом — вставити React лише туди, решту не чіпати

Останній рядок — важливий запобіжник. Вибір не бінарний. React можна додати пізніше на один екран, не переписуючи 42 шаблони. Тому рішення «лишаємось» нічого не закриває назавжди — воно просто не платить за міграцію наперед.
