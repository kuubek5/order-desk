# Бриф: які дані можна витягти з верстатів

Складено 12.09.26. Продовження теми, що обірвалась 02.07.26 в іншому проєкті.
Для нового чату: прочитати цей файл, далі за кроками. Інваріанти верстатів —
`CLAUDE.md` §14 («Верстати»).

## Мета

Знати про верстат більше, ніж «ріже / не ріже»: реальні години різання й
простої, наробіток і залишок ресурсу кожної фрези, заміни фрез, мотогодини
шпинделя, стан охолодження та повітря.

## Парк

- **5 старих RemiCORE** (за специфікацією — 350i, підтвердити). Назву `.iso`
  віддають у заголовку вікна.
- **Нові CORiTEC 150i PRO / 250i PRO+** зі `SmartControl.Dental` /
  `Dental Studio`. Назву програми з екрана JOBS читаємо глифами
  (`app/machine_newgen_job.py`). Еталонний для дослідів: SN `SN2023S1297`,
  `192.168.1.52`.

## Що вже живе в KuubMill

Лише зв'язок і «що фрезерується»: агент на ПК верстата, діагноз обриву (3
невдачі поспіль, стук у 445/135/3389), OCR заголовка й екрана JOBS. **Нічого
про фрези, знос, магазин, мотогодини в коді немає.**

Усе про фрези існує лише як план в ОКРЕМОМУ проєкті `C:\project_cnc_site`
(«CNC Tracker»): `cnc-tracker-data-spec.md` (джерело істини по полях),
`cnc-tracker-design-brief-v3-tool-changes.md`, і БД `cnc_tracker.db` з
таблицями `tool_slots`/`tool_readings`/`tool_changes`, наповненими ТЕСТОВИМИ
даними.

## Джерела даних: вердикт станом на сьогодні

| Джерело | Стан |
|---|---|
| INI на ПК старих RemiCORE | читання гарантоване (текст + наш агент уже там), **зміст не звірений** |
| Логи `C:\ProgramData\imes-icore\SmartControl\logs\*.log` | читаються без пароля; дають старт/стоп завдань, стан, температуру шпинделя; **зносу немає** (перевірено) |
| OPC-UA, порт 4840 (нові) | сервер живий, брандмауер пробито, TCP проходить; **блок — логін** (`UserTokenType: UserName`), обліковки немає |
| XML завдань (`SmartControlJobData.xsd`) | глухий кут: верстат видаляє job після архівації, живого файла не бачили |
| DLL інсталяції | код, не дані |
| `.iso` програми | програма фрезерування, до зносу стосунку не має |
| Екран | те, що вже робимо; числа лише піксель-у-піксель, інакше порожньо |

## Поля старих верстатів (зі специфікації, дослівно)

| Що | Файл | Поле |
|---|---|---|
| Координати 20 гнізд | `TchUni.INI` | `[ToolInClampPos_1..20]` → AxX/AxY/AxZ/AxA/AxB, MoveOrder |
| Системні позиції | `TchUni.INI` | `[ToolChangePos]`, `[EndPos]`, `[StartPosRef]`, `[SecLevel]`, `[LastPos]` |
| Тип фрези в гнізді | `ToolCfg.INI` | `[ToolChange_ToolTable]` |
| Фреза в шпинделі | `Toolstat.INI` | `ActTool` |
| Наробіток / ресурс | `ToolProperties.INI` | `ActRunTime`, `MaxRunTime` |
| Помилка фрези | `ToolProperties.INI` | `ErrStatusFlag` |
| Довжина й допуск | `ToolProperties.INI` | `RefPosZ`, `MinLength`, `MaxLength` |
| Час на одиницю | `ToolProperties.INI` | `AvgTimePerUnit` |
| Діаметр, оберти, швидкість | `ToolProperties.INI` | `Diameter`, `MaxSpeed`, `CuttingVelocity` |
| Мотогодини шпинделя | `Spindle.LOG` | бачили лише на фото |

Правила розбору зі специфікації: тисячні міліметра, `1073741823` = «немає
значення», час `ГГ:ХХ:СС`.

## Рішення, вже ухвалені в липні (не переобговорювати без причини)

- **Знос = мотогодини, не календар.** `ActRunTime` росте лише поки шпиндель
  ріже. Знос = `ActRunTime / MaxRunTime`.
- **Прив'язка до ГНІЗДА, не до фрези.** Тип у гнізді стабільний (гніздо 12 =
  1 мм), тож історія гнізда = історія фрез цього типу.
- **Заміна фрези = обнулення лічильника**, інших причин скиду немає. Падіння
  `ActRunTime` закриває попередній запис історії гнізда.
- Опитування повільних даних — раз на годину, не частіше.

## Відкриті питання (зі специфікації §8, досі не закриті)

- Чи рядки `ActRunTime` відповідають гніздам один-до-одного.
- Структура `Spindle.LOG` на повному файлі: чи є дати, чи лише суми.
- Точні UNC-шляхи й імена ПК усіх п'яти старих верстатів.
- Чи всі п'ять — та сама модель і та сама кількість гнізд.

## Що підтверджує вендор публічно

Опис SmartControl заявляє **вбудований контроль наробітку й поломки
інструмента**, контроль контуру охолодження, повітря й рівня рідини
([medicalexpo](https://www.medicalexpo.com/prod/imes-icore-gmbh/product-72794-1176387.html),
[imes-icore про 250i PRO+](https://www.imes-icore.com/company/news/article/introducing-coritec-250i-pro)).
Публічної документації на OPC-UA чи API **не знайдено** — тому офіційний шлях
один: запит у imes-icore на read-only доступ або інтерфейс даних.

## Галузева практика, якщо вендор закритий

- **Струмові кліщі (split-core CT)** на живлення шпинделя: без розриву проводів і
  без простою, $50–200 за датчик, дають «ріже / стоїть», завантаження,
  споживання; працюють на верстаті будь-якого року
  ([AMD Machines](https://amdmachines.com/blog/iiot-sensors-and-connectivity-for-legacy-equipment/),
  [MachineTracking](https://www.machinetracking.com/post/iot-sensors-legacy-cnc)).
  **Межа:** датчик не знає ні програми, ні коду аварії, ні номера фрези
  ([Caddis](https://www.caddissystems.com/insights-and-articles/cnc-machine-monitoring-complete-guide)).
- Лабораторії здебільшого ведуть ресурс фрез РУКАМИ: номер/штрихкод на фрезу,
  години в софті, межа за фактом появи відколів
  ([Roland DG / Whip Mix](https://info.whipmix.com/roland-quick-tip-how-to-keep-track-of-your-milling-bur-life)).
  Орієнтири: 2 мм чорнова по цирконію — 60–80 одиниць, буває 30–35; ПММА та
  інші матеріали зношують швидше
  ([Amony](https://www.hmntool.com/complete-guide-dental-cad-cam-milling-burs.html)).
  Тобто лічильник від самого верстата — краще за галузевий стандарт.

## План (за зростанням ціни)

1. **Один набір живих файлів зі СТАРОГО верстата** — `ToolProperties.INI`,
   `ToolCfg.INI`, `Toolstat.INI`, `TchUni.INI`, `Spindle.LOG`. Закриває три з
   чотирьох відкритих питань. Дешевше за все: агент уже на тих ПК, дописати
   йому читання текстового файла — години роботи. **Парсер писати лише після
   того, як побачили справжній файл** (урок заготовок: тестував на файлах, які
   сам і створив).
2. **Парсер логів нових верстатів** — години різання, простої, старт/стоп
   програм. Доступно без пароля й без дозволів; найбільша віддача «на годину
   роботи», бо відповідає на «чи завантажені верстати».
3. **Обліковка OPC-UA** — лист у imes-icore (текст готую, надсилає власник).
   Єдиний шлях до зносу на нових верстатах.
4. **Запас, якщо відмовлять** — струмові кліщі: години різання однаково на всіх
   верстатах, але без прив'язки до фрези.

## Що потрібно від власника

- Один набір INI з будь-якого старого верстата (агентом або руками).
- Рішення, чи надсилати лист у imes-icore.
- Імена/адреси ПК старих верстатів, якщо вони не збігаються з тими, що вже в
  Налаштуваннях.
