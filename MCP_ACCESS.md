# Діагностичний доступ до CRM (MCP)

Як дати Claude Code читати стан KuubMill — з цього ж ПК або з домашнього через
тунель WireGuard. Доступ **лише читає**: ні база, ні Google Таблиця, ні
налаштування через нього не змінюються.

## Що це дає

Замість «зроби скріншот Архіву», «вставь оце в PowerShell», «перешли звіт» —
структурована відповідь одним запитом: черга дня, журнал синку, паспорт роботи,
скільки запитів до Google за хвилину, пошук у лозі.

## Варіант 1: на цьому ж ПК (працює без налаштувань)

CRM уже віддає `POST /mcp` на своєму порті, і гейт пускає лише запити з цієї
машини. Конфіг підключення лежить у `.mcp.json` у корені проєкту:

| Назва | Адреса | Коли |
|---|---|---|
| `kmill` | `http://127.0.0.1:8000/mcp` | встановлена CRM (прод) |
| `kmill-dev` | `http://127.0.0.1:8002/mcp` | dev-сервер |

Проєктні MCP-сервери підтверджує користувач при першому запуску сесії
(`claude mcp list` покаже «Pending approval», поки не підтвердив).

## Варіант 2: з домашнього ПК через тунель

Схема: цеховий ПК **сам дзвонить** додому програмою WireGuard у MikroTik із
увімкненим «Back to Home». У цеху на роутері міняти нічого не треба.

```
домашній ПК ──Back to Home──▶ цеховий ПК (CRM) ──агент──▶ верстати
192.168.88.2                  адреса з тунелю              192.168.1.x
```

**Стукати треба на адресу тунелю** (поле `Addresses` у програмі WireGuard на
цеховому ПК), а не на `192.168.1.x`: цехова підсіть для діагностики не потрібна,
бо верстати й печі опитує сама CRM.

### У цеху, один раз

1. Налаштування → **Доступ по мережі** → увімкнути перемикач. CRM підніме
   окремий слухач, у якому є лише `/mcp`.
2. Там же взяти токен (показується **один раз** при створенні; загубив —
   перевипусти, старий одразу мертвий).
3. У програмі WireGuard дописати в конфіг тунелю `PersistentKeepalive = 25`.
   Без цього тунель «засинає», і вхідне з'єднання з дому до нього не доходить.
4. Брандмауер Windows: дозволити вхідний TCP на порт слухача. **Правило мусить
   покривати профіль «Загальнодоступна»** — інтерфейс WireGuard Windows
   зазвичай класифікує саме так, і правило лише для приватного профілю мовчки
   не працює. Обмеж джерело адресою домашнього ПК у тунелі.

### Удома, один раз

Токен **не кладеться в git**. Він живе у змінній середовища, а конфіг на неї
посилається:

```powershell
[Environment]::SetEnvironmentVariable('KMILL_MCP_TOKEN', '<токен з цеху>', 'User')
```

Потім у `.mcp.json` додається запис із адресою тунелю й заголовком
`Authorization: Bearer ${KMILL_MCP_TOKEN}`.

## Перемикачі, якими доступ закривається

| Перемикач | Де | Коли вимкнений |
|---|---|---|
| Тунель WireGuard | програма на цеховому ПК | дороги немає взагалі |
| «Доступ по мережі» | налаштування CRM | порт зникає з мережі |
| Токен | кнопка «перевипустити» | старий токен мертвий, навіть якщо порт відкритий |

## Якщо не працює

| Симптом | Де шукати |
|---|---|
| `Pending approval` | підтвердити проєктні MCP-сервери в Claude Code |
| `403` з локальної машини | гейт loopback: запит прийшов не з цього ПК — потрібен слухач із токеном |
| `401` | токен не той або перевипущений; узяти новий у налаштуваннях |
| немає з'єднання зовсім | тунель неактивний, немає `PersistentKeepalive`, або правило брандмауера не покриває профіль «Загальнодоступна» |
| `kmill_quota` каже «лога немає» | запущено не встановлену CRM: dev-сервер пише лише access-лог uvicorn без часу |

## Що саме віддається

`kmill_health`, `kmill_queue`, `kmill_order`, `kmill_sync_journal`,
`kmill_quota`, `kmill_log`. Усі помічені «лише читання»; секретів у відповідях
немає (лише ознака «задано»), імена клієнтів і номери нарядів — є.
