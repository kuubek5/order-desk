# Діагностичний доступ до CRM (MCP)

Щоб Claude Code бачив стан KuubMill — з цього ж ПК або з домашнього через
тунель. Доступ **лише читає**: ні база, ні Google Таблиця, ні налаштування
через нього не змінюються.

## На цьому ж ПК — нічого робити не треба

CRM уже віддає `/mcp` на своєму порті й пускає запити лише з цієї машини.
Конфіг підключення — у `.mcp.json` в корені проєкту (`kmill` — прод 8000,
`kmill-dev` — dev 8002). Claude Code питає підтвердження при першому запуску.

## З іншого ПК — три кроки

**1. Увімкнути.** Налаштування → «Доступ по мережі» → увімкнути. Токен
створиться сам.

**2. Передати один рядок.** Там же, у «Рядок для передачі», натиснути
«Скопіювати» й надіслати. У рядку вже є і адреса, і токен:

```
http://<адреса>:8011/mcp?t=<токен>
```

Якщо рядків кілька — потрібен той, чия адреса збігається з полем `Addresses`
у програмі WireGuard.

**3. Брандмауер, один раз.** На тому ж екрані є готова команда з кнопкою
«Скопіювати» — запустити в PowerShell від імені адміністратора. Вона пускає
вхідні на порт 8011 **у всіх профілях мережі**: інтерфейс WireGuard Windows
майже завжди вважається «Загальнодоступною» мережею, і правило лише для
«Приватної» мовчки не працювало б (ця пастка вже коштувала місяць хибного
діагнозу обривів верстатів).

## Як закрити доступ

| Дія | Наслідок |
|---|---|
| вимкнути перемикач у CRM | порт зникає з мережі за кілька секунд |
| «Перевипустити токен» | старий рядок мертвий, навіть якщо порт відкритий |
| вимкнути тунель WireGuard | дороги немає взагалі |

## Якщо не з'єднується

| Симптом | Що перевірити |
|---|---|
| `401` | рядок старий — узяти новий на екрані |
| немає з'єднання зовсім | тунель піднятий? команда брандмауера виконана? |
| з'єднання рве після простою | дописати `PersistentKeepalive = 25` у конфіг тунелю на цьому ПК |
| `Pending approval` | підтвердити MCP-сервери в Claude Code |
| `kmill_quota` каже «лога немає» | запущено не встановлену CRM: dev-сервер пише лише access-лог uvicorn без часу |

## Що саме віддається

`kmill_health` (стан), `kmill_queue` (черга дня), `kmill_order` (паспорт
роботи), `kmill_sync_journal`, `kmill_quota` (запас по квоті Google),
`kmill_log` (пошук у лозі).

Пристрої: `kmill_devices` (печі й верстати зі статусом і **віком** останнього
кадру), `kmill_frame` (сам кадр картинкою — весь або виріз зони печі),
`kmill_zones` (що читається в кожній зоні й чому поле порожнє). Кадр лише
найсвіжіший: історії не існує, на пристрій зберігається один файл.

Усі лише читають. Секретів у відповідях немає; імена клієнтів і номери
нарядів — є, як і те, що видно на екрані печі чи верстата.
