Рішення власника 07.10.26: з чотирьох макетів (`design/mailqueue_variant_{A,B,C,D}_20261007.png`,
інтерактивний `design/mailqueue_variants_20261007.html`, огляд з телефону —

є перемикач; у вимкненому стані екран пошти лишається таким, як зараз («зараз працює»).

## Що вже є (і від чого відштовхуємось)

Внизу пошти живе дзеркало черги `.qmir` «Прийняте з пошти» (`mail_triage.html` ~367):
- дані — `app/services/mail_mirror.py::mail_mirror_orders(db)`: `source == "email"`, не в архіві,
  робоча вкладка дня (`business_tab_today`, у вихідні — п'ятниця), `Order.id DESC`;
- рендер — `_mail_queue_mirror.html` → `_queue_table_head.html` (без сортування) + `_order_row.html`,
  контекст `statuses` + `focused_ids` (сторож `test_order_focus` вимагає `focused_ids` на кожному
  рендері рядка); ширини стовпців бере `queue.js` з `.q2 .tablewrap table.qtable`;
- полл — `GET /mail/queue-mirror` кожні 15 с (`[!document.hidden]`), свопає лише тіло `.qmir-body`;
  там же дотягуються іконки тек (`attach_mail_mirror_folder_uris`, `attach_job_code_folder_uris`);
  `mail.js` пропускає своп під час набору й зберігає скрол `.tablewrap`;
- згорнуто за замовчуванням (`KMStore mailMirrorCollapsed`, інлайновий скрипт одразу після секції);
- CSS — `.qmir*` у `v2a_mail.css` (14 правил).

Усе це лишається: варіант A — розширення цього блоку, не новий екран.

## Що зробити

### 1. Перемикач джерела (per-operator, зберігається)

Нове поле `User.mail_dock_scope` (міграція) зі значеннями `("", "mail", "lab", "all")` у
`look_prefs.MAIL_DOCK_SCOPES`:
- `""` = канон = як зараз (лише прийняте з пошти). На дроті канон має ВЛАСНЕ слово `"mail"`
  (пастка «порожнє поле = поля не було», CLAUDE.md §14), у базі кладеться `""`;
- `"lab"` = прийняте з пошти **+ лабораторія** (`source == "lab"`);
- `"all"` = уся вкладка дня (лаба + табличні клієнти + пошта).

Зберігається тим самим роутом шестерні `POST /ui/look` (`auth.py`, `scope="mail"`) через
`apply_mail_look(..., dock: str | None = None)` — `None` = не чіпати, як `view`. Межі/переліки
дублює `lookgear.js`, за розбіжністю стежить `tests/test_mail_look_prefs.py` — додати туди.

UI: сегментований перемикач у шапці доку `.qmir-head` — «Прийняте з пошти N · + Лабораторія N ·
Уся вкладка N» (як на макеті). Клік = `fetch` на `/ui/look` + одразу `htmx.ajax` полла
(не чекати 15 с). Заголовок доку: «Прийняте з пошти» при `""`, «Черга» при `lab`/`all`.

### 2. Фільтр готовності для лаби

`User.mail_dock_ready` зі значень `queue_filters.READY_FILTERS` (`all / not_ready / can_take /
in_work`), дефолт `"can_take"` — це те, що CAM-оператор бере між листами. Чипи в шапці доку
з лічильниками (`count_by_readiness`). Застосовується до **лабораторних і табличних** рядків;
рядки пошти показуються як зараз, без фільтра (їх і так мало, і оператор щойно їх прийняв).
Теж через `apply_mail_look(..., dock_ready=...)`.

### 3. Дані: `mail_mirror_orders(db, *, scope, ready)`

Один запит `Order` вкладки дня (`archived_at IS NULL`, `selectinload(material)`), далі:
- `""` → рівно теперішня логіка (тест на незмінність!);
- `"lab"` → блок пошти як зараз (id DESC) + блок лаби в **порядку таблиці** (`row_number ASC`,
  CLAUDE.md §2: порядок = таблиця, полл не пересортовує), відфільтрований `filter_by_readiness`;
- `"all"` → усі роботи дня в порядку таблиці, `filter_by_readiness` до всіх, крім пошти.

Між блоками пошти й лаби — один рядок-роздільник (`<tr class="qmir-sep">`, підпис «Лабораторія ·
можна брати 5»), щоб два порядки не читались як один. `_order_row.html` — лише через той самий
контекст, що в черзі (`orders._row_context` або рівно той набір, що передає дзеркало зараз).

Лічильники для перемикача (3 числа) і чипів готовності — з того самого вибраного набору,
без додаткових запитів.

### 4. Висота доку

Смужка-ручка (`.grip`) над шапкою; тягнеться по вертикалі, значення `User.mail_dock_height`
(`Bounds(160, 720)`, 0 = як було) через `apply_mail_look(..., dock_height=...)`, як ширина списку
`mail_list_width`. Згортання лишається клієнтським (`KMStore`), як зараз.

### 5. Поведінка у вимкненому стані

`mail_dock_scope == ""` → шапка доку та сама, що сьогодні, плюс лише сегментований перемикач
(щоб було чим увімкнути); дані, полл, згортання, CSS — без змін. Тест: HTML дзеркала при `""`
байт-у-байт збігається з теперішнім, крім блоку перемикача.

## Що ще зачіпає (перевірити ДО коду)

- `tests/test_route_inventory.py` — нових роутів нема (`/mail/queue-mirror` читає налаштування з
  `user`), знімок не міняється; якщо з'явиться новий — міняти свідомо.
- `tests/test_frontend_assets.py` — JS-синтаксис і порядок скриптів.
- `tests/test_order_focus.py` — `focused_ids` на кожному рендері рядка (дзеркало вже так робить).
- `queue.js::applySavedWidths` — збережені ширини стовпців черги застосуються й тут (вже так);
  комірка наряду `.oid`, не flex на `td` (§14).
- Inline-правка Sum3D/статусу в рядках — ті самі роути `/orders/{id}/…`, що в черзі, точкові свапи
  `#order-row-{id}`; запис у таблицю — `await_on_writeback`, п'ять місць `sum3d_pending` не чіпаємо.
- Полл у прихованій вкладці спить (`[!document.hidden]`); на пів-екрані (<960px) док під карткою —
  перевірити, що згорнутий док не з'їдає висоту списку.
- Вихідні: лаба береться з п'ятничної вкладки (`business_tab_today`) — як дзеркало зараз.
- `_mail_queue_mirror.html` також рендерить `/mail/queue-mirror` для порожнього набору
  (`qmir-empty`) — текст порожнього стану під кожен scope свій.

## Тести (мінімум)

1. `scope=""` → той самий набір і порядок, що й до змін (прибитий знімок через `mail_mirror_orders`).
2. `scope="lab"` → пошта (id DESC), далі лаба (row_number ASC), табличних клієнтів немає.
3. `scope="all"` → порядок таблиці, пошта без фільтра готовності, решта — за `ready`.
4. `ready="can_take"` за замовчуванням; `"all"` показує все.
5. `apply_mail_look(dock=None)` не чіпає збережене; `"mail"` → у базі `""`; невідоме → `LookError`.
6. `lookgear.js` дзеркалить `MAIL_DOCK_SCOPES`/`READY_FILTERS`/`Bounds` (розширити `test_mail_look_prefs`).
7. Рендер `/mail/queue-mirror` для кожного scope без 500 (через `tests/asgi_client.MiniClient`).
